# 명세·작업 나누기를 기계가 검사

## 의도
사람이 명세·작업 나누기를 제대로 보지 않고 넘기고 있다(사용자 말: "어차피 지금 나 스스로가 그냥 넘기고 있드라구 재대로 보지도 않고"). 잘 됐는지 판단을 기계 몫으로 넘긴다.
- ① grilling에서 정한 것·카드 성공 조건이 명세와 작업 완료 조건에 빠짐없이 들어갔나, 없던 말이 끼어들지 않았나
- ② 작업마다 끝나면 확인할 수 있는 결과가 있나

정한 범위 (grilling 2026-11-26):
- 누가: 규칙 검사(모양: 작업마다 완료 조건이 있나, 앞선 작업이 실제로 있나) 먼저, 그다음 명세를 쓰지 않은 AI가 뜻을 대조. AI는 코드 리뷰와 같은 실행 방식(설정된 리뷰 명령)을 쓴다.
- 대조 기준: 작업 카드 전부(의도·범위, 성공 조건, 판단 필요의 답, 고른 안과 이유).
- 빠진 말·끝나면 볼 것 없음 → AI가 명세·작업을 고치고 다시 검사, 최대 2번. 그래도 남으면 사람에게 질문.
- 끼어든 말 → 한 줄씩 사람에게 "명세에 'OO'가 들어갔습니다. 원하신 건가요?"
- 시점: 작업 파일을 쓴 뒤, "돌려" 전. 통과 전에는 작업이 시작되지 않는다. 결과는 "돌려" 직전 요약에 한 줄. 통과 뒤 명세·작업이 바뀌면 다시 검사(확인 번호처럼 내용에 묶음).
- 원본 to-tickets의 "잘게/굵게·순서" 질문은 그대로 두고, 물을 때 "파일을 쓴 뒤 기계가 검사하고 고칩니다. 이대로 쓸까요?"로 예고. 원본 수정 없음.
- 범위 밖: "명세 만들어 줘"·"작업 나눠 줘"를 사람이 직접 말해야 시작되는 것(11-19 고민과 함께 따로).
