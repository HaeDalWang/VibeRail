# 사람이 고른 설계안·명세에 확인 번호 붙이기

## 의도
사람이 고른 설계안과 명세가 그 뒤에 바뀌면, 예전 답을 그대로 쓰지 않고 바뀐 부분을 보여 주며 다시 묻는다(백로그 3번, plannotator 계획 비교 본뜸). 검사 기록이 코드 상태(트리 해시)에 묶이듯 사람의 결정도 내용에 묶는다.

범위(grilling 답, 2026-11-23):
- 대상: 고른 설계안 하나 + 명세. 각각 짧은 확인 번호
- 바뀐 것의 기준: 띄어쓰기·줄바꿈·들여쓰기만 다르면 같은 내용. 설계안은 고른 안의 칸만(이름·요약·그림·장점·비용·signature·seam·그 안의 질문). 고르지 않은 안은 상관없음
- 고를 때: 설계안 화면의 복사 글에 확인 번호 자동 포함. 질문은 늘지 않음
- 명세: 작업 목록이 생겨 "돌려"를 받을 때 qh가 "이 명세(확인 번호 …)대로 시작할까요?"를 묻고, "돌려"가 그 답
- 바뀌면: 응답 끝·PR 전에 막고 다시 묻는다. 예전→지금 바뀐 줄을 함께 보이고 완료 리뷰 화면에도 표시
- 예전 내용은 git 기록에서 찾는다. 못 찾으면 "바뀌었다, 지금 내용 전체를 다시 보세요"만 보이고 다시 묻는다
- 확인 번호 없는 기존 카드: "지금 내용으로 계속할까요?"를 한 번 묻는다
- 브랜치: feat/guided-review 위에 새 브랜치
