# 0003. 대상은 "개발자는 아니지만 엔지니어인 사람"이다

- 날짜: 2026-11-25
- 상태: 채택

## 결정
- VibeRail은 만든 사람이 쓰기 쉬운 도구를 먼저 만든다. 대상은 개발자 출신은 아니지만 인프라·운영 같은 엔지니어 배경이 있는 사람이다. "개발을 전혀 모르는 바이브코더"는 대상이 아니다.
- 성격은 에이전틱 코딩 도우미다. 검사 층(자동 차단)과 순환 층(질문 받기, 설계안 고르기, 테스트 먼저, 구조 후보 고르기)을 둘 다 유지한다. 사람이 고르고 이유를 적는 지점은 이 대상이 판단할 수 있다고 본다.
- 형식 원칙(그림 먼저, 짧게, 사용자에게 명령어를 치게 하지 않음)은 그대로 둔다. 바뀌는 것은 독자 정의와 README 첫 줄의 약속뿐이다.
- 이름 VibeRail은 유지한다.
- 설치 때 고르는 사용자 수준(비개발자/개발자) 갈림은 지금은 둔다. 사람 배경에 맞춘 말 바꾸기(백로그 G2)를 할 때 함께 고친다.

## 이유
- 실사용 기록은 만든 사람 한 명(엔지니어 배경, 개발자 아님)뿐이다. 순수 비개발자가 써 본 적은 없다. 근거가 받쳐 주는 범위까지만 약속한다.
- 차별점인 Pocock 순환(ADR 0001)은 설계 판단을 사람에게 요구한다. 개발을 전혀 모르는 사람에게는 이유 없는 승인이 되기 쉽다.

## 버린 대안
- 순수 바이브코더용: 순환 층을 기본값으로 숨기고 검사 층만 남긴다. 작아지지만 차별점이 줄고, 근거도 없다.
- 두 대상을 다 약속하는 지금 상태: 판단 기준이 두 개가 되어 결정마다 흔들렸다.

## 다시 볼 조건
- 엔지니어 배경이 아닌 사람이 실제로 쓰겠다고 하거나, 그런 사람의 체험(sandbox)에서 설계안 고르기를 문제없이 해낼 때.
