# README 규칙

README를 고칠 때 이 규칙을 먼저 따른다. 기준판은 커밋 `7d4eb07`의 README다.

## 독자

- 개발을 해 본 적 없는 사람이다. 긴 글은 읽지 않는다. 심하면 3줄도 읽지 않는다.
- 기술적으로 어떻게 되는지는 궁금해하지 않는다. "깔면 나한테 무슨 일이 생기고, 그래서 왜 좋은지"만 알면 된다.

## 규칙

1. **그림이 먼저, 글은 그림 사이에 한 줄.** 섹션마다 그림·캡처 하나와 한 줄 설명을 둔다. 글 문단은 쓰지 않는다.
2. **실제 화면을 캡처한다.** 질문 화면과 결과지는 지어내지 않는다. 시험 프로젝트에 qh를 실제로 깔고 돌려서 찍는다. 화면이 바뀌면 다시 찍는다.
3. **사용자가 겪는 순서대로 쓴다.** 붙여 넣기 → 질문 화면에서 고르기 → 평소처럼 일 시키기(검사, 되돌림, 질문) → 결과지 보기.
4. **사용자가 하는 일은 붙여 넣기와 말하기뿐이다.** 명령어를 치게 하지 않는다. 할 일은 "AI에게 이렇게 말하세요" 표로 준다.
5. **결과지로 효과를 보여 준다.** "깔기 전 → 지금"이 좋아진 숫자로 보이게 한다.
6. **기술 내용은 README에 두지 않는다.** 명령, 설정, 검사 목록은 [reference.md](reference.md)에, 구조는 [architecture.md](architecture.md)에 둔다. README에는 맨 끝에 링크만 둔다.

## 그림 만들기

- 흐름 그림은 `docs/images/*.svg`에 둔다. 배경색을 직접 칠해 GitHub 다크 모드에서도 보이게 한다.
- 캡처: 시험 프로젝트에서 `qh ask`와 `qh measure --backfill`을 돌린다. 만들어진 HTML을 로컬 서버(127.0.0.1)로 열어 `playwright-cli screenshot`으로 찍는다(file://로 열면 빈 화면이 찍힌다). 필요한 부분만 `sips -c`로 잘라 `docs/images/`에 넣는다.
- 캡처에 실제 회사·고객·개인 정보가 찍히면 안 된다. 시험 프로젝트만 쓴다.
